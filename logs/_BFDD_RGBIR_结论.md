> 数字来源：`04_results/eval/bfdd_probe_rgbir.json` 与

## 一、为什么这件事此前被认为是「做不到」

`logs/_bfdd_modality_compare.txt` 的总结段原话：

> 「要真正回答，需要**同时保留全部 RGB 通道并加入 IR** 的 4 通道模型；
> 而 ultralytics 的数据加载是 3 通道、4 通道还会破坏预训练权重的加载
> ⇒ **本轮预算内未解决**，已列为后续。」

这个判断**指向了两个真实的约束**（我们复核后确认它们属实）：

| # | 约束 | 源码事实 |
|---|---|---|
| 1 | **数据加载只认 1/3 通道** | `ultralytics/data/base.py:134`：
`self.cv2_flag = cv2.IMREAD_GRAYSCALE if channels == 1 else cv2.IMREAD_COLOR`
⇒ 4 通道 PNG 会被 `IMREAD_COLOR` **静默截断成 3 通道** |
| 2 | **首层卷积装不下 4 通道** | `model.model[0].conv` = `Conv2d(3, 32, 3, 3)`，
直接建 4 通道模型会**丢掉预训练权重**（而公平性前提是各模态同初始化） |

**但「两个约束」不等于「做不到」**：两者都各有**一个明确的改动点**。
本轮把这两个改动点都实现了，并且**不修改 ultralytics 安装**（见 §三）。

## 二、★ 一个关键的数据发现：原料早就齐了

复核 `01_data/raw/_public_datasets/bfdd/` 时发现：**IR 模态与融合变体早已解压在盘上**，
此前的研究只用了其中一部分：

```
01_data/raw/_public_datasets/bfdd/_yolo/
├── rgb/      # [R,G,B]              (686 train / 152 val)
├── ir/       # 红外伪彩三通道         (686 / 152)
├── irgray/   # gray(IR) 复制三通道    (686 / 152)
├── fuse/     # [R,G,IR]  ← 换掉 B    (686 / 152)
├── ctrl/     # [R,G,gray(RGB)] 对照  (686 / 152)
└── crackdet/ # 7 类检测子集，仅 152 张 val
```

且**文件名在四个模态间完全一致**（`DJI_YYYYMMDDHHMMSS_NNNN`），
即 RGB 与 IR 是**严格对齐的像素对**。实测核验：

| 核验项 | 结果 |
|---|---|
| RGB / IR / irgray / fuse 四者的 train+val 图数 | **686 / 152，四者全等** |
| 尺寸 | 全部 **640×512** |
| `fuse` 第 3 通道 == `irgray` 灰度 | **152/152 逐像素全等** |
| `fuse` 前 2 通道 == `rgb` 前 2 通道 | **逐像素全等**（maxdiff = 0） |

⇒ 结论：**`fuse = [R, G, IR]` 就是「把 B 换成红外灰度」**。
这正是既有对照 `ctrl = [R, G, gray(RGB)]` 要隔离的那一项，
但 `fuse`/`ctrl` **两者都丢掉了 B 通道**，所以它们**回答不了**
「保留完整 RGB 时外加 IR 是否有增益」。**这就是本轮的缺口**。

## 三、实现：三个改动点（全部为**运行期 patch**）

**核心设计决策：不修改 `D:/下载/Lib/site-packages/ultralytics`。**

理由：改安装会让本工程的结果依赖一个被改过的第三方包 ——
复现者装官方 ultralytics 就跑不通，且升级即失效。
⇒ 全部改动集中在 `02_code/_bfdd_rgbir_patch.py`，可审计、可回滚。

### 改动点 1 —— 数据加载支持 4 通道

patch `BaseDataset.load_image`：`channels == 4` 时用 `cv2.IMREAD_UNCHANGED`
真读 4 通道，并**强制断言**通道数。

> ★ 断言而非容错，是刻意的：**「静默降维」比崩溃更坏** ——
> 它会让 4 通道实验悄悄变成 3 通道实验，而结果仍然看着「正常」。

### 改动点 2 —— 首层 3→4 权重膨胀（weight inflation）

```python
new = nn.Conv2d(4, old.out_channels, ...)
new.weight[:, :3] = old.weight            # 前 3 通道：逐元素原样保留
new.weight[:,  3] = old.weight.mean(dim=1)  # 第 4 通道：对输入通道取均值
```

**★ 必须如实说明这个初始化的精确性质（实测，勿误述）**：

它 **不是**「无扰动的恒等嵌入」。设原首层输出 `y3 = Σ_k W_k * x_k`，膨胀后

```
y4 = y3 + Σ_k mean_j(W_jk) * IR_k          （mean_j 是对**输入通道**取均值）
```

实测（随机权重、`IR = mean_k(x3)`）：该**额外项**的模长约为原输出的 **0.19 倍**，
即「有扰动但很小」。之所以仍选 mean 而非 zero：
zero 会让第 4 通道在初始时刻**恒不激活**（须从零学起，收敛更慢）；
mean 让它一开始就携带「RGB 均值图」这一合理先验，
**而前 3 通道的预训练特征被完整保留** —— 这才是公平性的关键。

本次实验所用 mode = **`mean`**，
并已把 `src_shape → dst_shape` 与 mode 一并落盘（`_bfdd_rgbir_patch_record.json`）。

### 改动点 3 —— 训练前自检

`assert_ready()` 强制三项：① 数据集 yaml 含 `channels: 4`；
② 抽样的图**真是 4 通道**；③ 模型首层 `in_channels == 4`。
任一不过即中止 —— 绝不允许「以为在跑 4 通道、实际在跑 3 通道」。

### 数据构建

`02_code/_bfdd_build_rgbir.py` 产出 `rgbir/`，通道序 **BGRA = [B, G, R, IR]**
（YOLO/OpenCV 原生 BGR 语义，前 3 通道语义与 `rgb` 完全一致；第 4 通道固定为 IR）。
落盘用 **PNG**（JPEG 不支持 4 通道）。标签与 `rgb` **硬链接**（同一划分、同一标签）。

构建自检：抽样 20 张，**第 4 通道 == IR 灰度 20/20 通过**；
train 新建 686 张 / val 新建 152 张。

## 四、实验口径（**与既有四个模态对齐，单变量**）

| 项 | 6 个模态是否一致 |
|---|---|
| epochs | 80 |
| imgsz | 512 |
| batch | 8 |
| seed | 0 |
| 预训练初始化 | 同一份 `logs/_yolo11n-seg.pt` 的 3 通道权重（4 通道经膨胀） |
| 划分 / 标签 | 同一份（`rgb` 的 labels 硬链接） |
| conf（IoU 统计） | 0.25 |
| IoU 实现 | 同一份（预测掩膜并集 vs 真值掩膜），**不用 mAP 替代** |

⚠️ **唯一偏离**：`workers = 0`（既有 5 个模态用的是 `workers=4`）。
原因：4 通道每张图多一路数据，`workers=4` 时**反复被静默杀掉**
（进程无 traceback 消失，日志停在自检之后）；`workers=0` 可稳定跑完。
**这是本实验已知的第二变量**，故报告须注明（沿用项目纪律：
跨 workers 做 A/B 时 workers 是第二变量）。

用时 73.06 min，落盘 80 轮。

## 六、判读与边界（**必须如实声明**）

**本实验回答了**：在**保留完整 RGB 通道**的前提下外加一路红外，
5 类分割的掩膜 IoU 是否提升（上表逐类给出）。
这是 `fuse`/`ctrl` 因「丢掉 B」而**结构性无法回答**的问题。

**本实验仍然不能回答**：

1. **不能说「IR 能看见空鼓」**。BFDD 的掩膜是**人工标注**的，
   标注者很可能在**可见光图**上判读 ⇒ 标签编码的是「可见光可见的证据」，
   任何模态去预测它都受此约束。本实验只回答
   「**IR 通道是否携带独立信息**」这一**必要非充分**条件。
2. **单次运行、单 seed** ⇒ 类间较小的 Δ **不构成结论**
   （沿用项目纪律：模型间差须超过噪声量级才算真实）。
3. BFDD 仅 **152 张 val / 5 类**，绝对 IoU 低是数据规模与任务难度的产物；
   **跨模态的相对比较**才是本实验的读数。

## 七、兼容性与风险（交付评估用）

| 项 | 结论 |
|---|---|
| **预训练权重** | **不破坏**：首层 3→4 膨胀，前 3 通道逐元素保留；其余层完全复用 |
| **与既有模态可比性** | **可比**：同划分 / 同标签 / 同超参 / 同初始化来源 |
| **推理部署** | ⚠️ **不可直接用现成 ONNX/TensorRT 导出流程**：4 通道需重新导出，且需 4 通道预处理 |
| **弃权 / OOD 机制** | 不受影响（走 `grade.py`，与输入通道解耦） |
| **ultralytics 升级** | patch 依赖 `load_image` 与 `model.model[0].conv` 的结构；升级后须复验 |
| **主交付包** | **不引入**：本方案仅用于 BFDD 外部验证；主模型仍为 3 通道 |
