### 9.4 时间演化：为什么本系统**不作**预测（边界声明，2026-09-26 新增）

> 本节是**主动的边界声明**，不是"没做"的托词。
> 它与本报告主线「**知道自己什么时候不该给结论**」**完全同构**：
> §2 讲的是「单张图上什么时候不该给结论」，本节讲的是「**整个系统什么时候不该给演化结论**」。
> 完整版：`logs/_BFDD_P4_时间演化边界声明.md`。

**问题**：既然系统能测出「裂缝宽 0.35 mm」，那能不能进一步回答
**这条裂缝未来会不会扩展？这面墙什么时候需要复检？**

**本系统明确回答：不能，并且我们不打算在没有数据的情况下假装能。**
理由不是"技术不够"，而是**数据里根本没有时间维度**。

#### 9.4.1 数据事实：本工程内不存在任何「跨时间的纵向重复观测」

| 检查项 | 实际结果 |
|---|---|
| 拍摄日期 / 时间戳字段 | **无**。标注 txt 只有 5 列 `cls cx cy w h` |
| 图片 EXIF 拍摄时间 | 抽样 400/11404 张，`EXIF keys = []`，`DateTime*` 命中 **0** |
| 文件名中的日期 / 批次 / 楼号 | **无**（纯序号 / Roboflow 哈希） |
| 同一栋楼的多次巡检 | **无**。同源多图是**同一次拍摄**的连拍/增强（2848 图里 distinct 基准名仅 1866） |
| 同一次拍摄的纵向痕迹 | **被主动清除了**（L1 MD5 去重 + L2 dHash≤3 近似去重，§4.1） |
| 照片收集站的 `created_at` | 字段**存在**，但**投稿 0 条**（`SELECT count(*) = 0`） |
| `annotations.csv` 的 `created_at` | 27 行全为同一天，且是**标注员创建时间**，不是拍摄时间 ⇒ **伪时间** |
| BFDD 的无人机航班时间戳 | **有**（`DJI_YYYYMMDDHHMMSS`），但只覆盖 **4 天的单次航测战役**；其"连续帧"是**沿相似轨迹的空间冗余**，不是纵向重复 |
| 全部实验产物 | 分层维度是 `deg` / `scale` / `GSD`，**没有一处按时间或批次分层** |

**一句话**：工程内的"多图"全都是**同一时刻、同一批次内的空间冗余**，
不存在任何**跨时间的纵向重复观测**。

#### 9.4.2 能做 vs 不能做（如实划分）

**能做（都是横截面 / 当下状态，不是时间预测）**：
① 单图当下状态（类别 / 尺寸 / 国标分级 / 风险等级）；
② **可判读性预测**（给定 GSD 与图像质量 → 能否支撑毫米级结论，即弃权机制）；
③ 同一次采集内的**空间聚合**（多帧取中位数、跨段拼接整立面、跨帧一致性）。

**不能做（以现有数据，无论如何都做不到）**：
① 缺陷劣化 / 演化趋势（T2 相对 T1 的变化、裂缝扩展速率）；
② 剩余寿命 / 失效时间预测（生存分析、风险评分随时间的迁移）；
③ 任何**以时间 / 批次为自变量**的时序模型 —— 数据里**没有这个自变量**；
④ 跨巡检的异常漂移检测 —— 无同一对象的重复观测，**无法配对**。

> 已把「换赛道到赛道一（时序）」列为**假挑战**（理由正是"外墙筛查是单图任务，没有时序维度"）。
> 本节把那条判断**从"不做"升级为"有据可查的边界声明"**。

#### 9.4.3 ★ 要让它"能做演化预测"，缺的唯一关键数据

> **同一建筑 / 同一墙面、跨不同日期、带可对齐身份键（楼号 + 位置 + 拍摄时间）的 ≥ 2 次重复拍摄。**

三个要件**缺一不可**：跨日期（不是同一天连拍）、同一对象（否则无法配对）、
可对齐的身份键（否则"同一天拍的两面墙"也配不上）。
而且现状是**连"同一次拍摄"的纵向痕迹都被去重清掉了**
⇒ 正确顺序是 **先建采集与台账机制，再谈演化预测**：

1. 收集站加字段：`building_id`（楼号）、`position`（位置/坐标）、`capture_time`（优先读 EXIF，读不到用上传时间并**标注来源**）；
2. **去重策略分离**：训练/评估用的划分**继续去重**（避免泄漏），
   但**原始台账必须保留重复记录**（否则纵向数据被自己的清洗流程销毁）；
3. **最小可行验证**：同一面墙、间隔 ≥ 1 个月、≥ 2 次拍摄，即可开始做
   「**变化检测**」而不是「演化预测」（前者只要求配对，后者还要求机理）；
4. **诚实地命名**：在拿到 ≥ 3 个时间点之前，**只写"变化检测"，不写"预测"**。

#### 9.4.4 建议的对外表述

> 「我们**没有**做缺陷随时间的演化预测，这不是遗漏，而是数据条件的直接后果：
> 工程内不存在任何跨时间的纵向重复观测——无日期字段、图片 0 EXIF、
> 同一栋楼无重复巡检、收集站投稿 0 条；唯一的带时间戳数据（BFDD）是 **4 天的单次航测战役**。
> 我们把这条边界写清楚，并给出补足它所需的最小条件。
> 这与本系统"**知道自己什么时候不该给结论**"的主线是同一件事——
> 只不过这次"不该给结论"的范围是**整个时间维度**。」
