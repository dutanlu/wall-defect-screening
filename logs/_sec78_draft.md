### 7.8 类别长尾的损失函数优化：逆频率类平衡实验（2026-09-23 新增）

> ⚠️ **本节数字为占位，待 `v11s640_clsbal` 跑满 100 轮并评估后回填。**

#### 7.8.1 动机：45.6 : 1 的类别长尾

本项目训练集的类别实例数极度不均衡（**train 1995 图**，逐类实例数由
`get_class_counts()` 实测读取，与标签点数逐类一致）：

| 类别 | 实例数 | 占比 |
|---|---|---|
| rust | **9433** | 74.7% |
| exposed_rebar | 973 | 7.7% |
| efflorescence | 841 | 6.7% |
| delamination | 486 | 3.8% |
| moss | 392 | 3.1% |
| crack | 299 | 2.4% |
| **spalling** | **207** | **1.6%** |

**最大类 / 最小类 = 9433 / 207 = 45.6 : 1。**

在标准 BCE 分类损失下，每一类的梯度贡献与其样本数成正比 ⇒
**`rust` 一类就贡献了约 3/4 的定位/分类梯度**，而 `spalling`
（测试集里 CI 半宽最大、最难检的那一类）只占 1.6%。
这既是模型层面的问题，也**正面回应了我们自己反复强调的长尾问题**
（见 §9 能力边界对稀有类的声明）。

#### 7.8.2 方法：`cls_pw` 逆频率加权（不改一行源码）

ultralytics 8.4.138 **内置**类平衡损失选项 `cls_pw`
（`ultralytics/cfg/default.yaml:107`，默认 `0.0` 即关闭，取值范围 `[0, 1]`）：

$$w_c=\left(\frac{1}{n_c}\right)^{p_w},\quad \text{再归一化使 } \overline{w}=1$$

权值逐类乘到 cls 分支的 BCE 上（`ultralytics/utils/loss.py:438-441`
`bce_loss *= self.class_weights`）。链路为：

```
train.py:157-165  get_class_counts() + compute_class_weights()
        ↓
train.py:167-186  set_class_weights()
        ↓
engine/trainer.py:415  （_setup_train 内、dataloader 建好之后）
        ↓
utils/loss.py:438-441  bce_loss *= self.class_weights
```

**本实验取** $p_w = 0.5$ **（平方根逆频率）**。取值理由：
- $p_w = 1.0$（完全逆频率）会把 `rust` 压到 0.049、`spalling` 抬到 2.238，
  权重跨度 45 倍，**在单种子实验下极可能把模型拉向过拟合稀有类噪声**；
- $p_w = 0.25$ 太接近基线，改动幅度不足以作为一次「损失函数优化」证据；
- $p_w = 0.5$ 把有效损失占比从 **45.6 : 1 压到 6.75 : 1**，
  且在 `crack`（1.349）/`spalling`（1.622）等稀有类上是**温和**提升，
  不是激进重加权。

实测权重表（`logs/_CLSBAL_WEIGHTS.txt`）：

| 类别 | $w_c$（$p_w$=0.5） | 原始占比 | 加权后有效损失占比 |
|---|---|---|---|
| crack | 1.349 | 2.4% | 3.2% |
| spalling | **1.622** | 1.6% | 2.6% |
| efflorescence | 0.804 | 6.7% | 5.4% |
| exposed_rebar | 0.748 | 7.7% | 5.8% |
| rust | **0.240** | 74.7% | 17.9% |
| delamination | 1.058 | 3.8% | 4.0% |
| moss | 1.178 | 3.1% | 3.7% |

**原始 45.6 : 1 → 加权后 6.75 : 1。**

#### 7.8.3 参数生效性的三重验证（★ 这一步是本节的关键）

「开了某个损失项」和「损失项真的生效」是两件事 ——
本项目已在 `copy_paste` 上踩过**静默 no-op**（`ultralytics/data/augment.py:1921-1924`
对纯检测数据集原样返回、不报警告）。因此本实验做了三层独立验证：

| 层 | 验证内容 | 结果 |
|---|---|---|
| **L1** 配置层 | `get_cfg(overrides={"cls_pw":0.5})` 是否接受；`cls_pw=1.5`/`-0.1` 是否被拒 | ✅ 通过（正确报 `ValueError`）；`cls_pw_typo` 报 `SyntaxError` |
| **L2** 运行时层 | `trainer.model.class_weights` 是否被真正赋值 | ✅ 见下（首轮 FAIL，归因后通过） |
| **L3** 损失效果层 | `rust` 在总 cls loss 中的占比是否下降 | ✅ 由 10.9% 降至 2.5% |

**L2 的首轮 FAIL 与归因（值得记录的方法论）**：
首次探测用 `fraction=0.02`（抽 2% 样本）观察到
`class_weights = [0.383, 0.647, 0.139, 1.711, 1.711, 1.711, 0.699]` ——
多类权重**并列相同**（三个 1.711），与全量复算不符。
连续两次反解尝试均失败（反推出 counts < 1，不可能）。
**正解是直接读中间量**：不再反解，改用 `on_pretrain_routine_end` 回调 +
`tr.get_class_counts()`，`fraction=1.0`。结果：

```
get_class_counts()                 = [299, 207, 841, 973, 9433, 486, 392]
按公式复算权重                      = [1.3492, 1.6216, 0.8045, 0.7479, 0.2402, 1.0583, 1.1783]
trainer.model.class_weights（实测）  = [1.3492, 1.6216, 0.8045, 0.7479, 0.2402, 1.0583, 1.1783]
```

**逐位相同。归因：`fraction=0.02` 把稀有类采成 0 实例，
`np.where(counts==0, 1.0, ...)` 统一置 1.0，产生「多类权重并列」的假象。
⇒ 通路完好，是探测设置的问题。**

> **★ 方法论沉淀**：验证「参数生效」时，
> ① 不要用 `fraction<1` 探测（抽样会扭曲类分布）；
> ② 不要反解中间量（反解失败无法区分「通路坏」与「假设错」）；
> ③ **直接取权威中间量**，取数时点在 `on_pretrain_routine_end`（dataloader 已建、
> 权重已设）。该流程已固化为项目技能
> `.workbuddy/skills/ultralytics-param-activation-check/SKILL.md`。

#### 7.8.4 A/B 设置与口径诚实说明

**对照组**：`v11s640`（基线，`cls_pw=0.0`）与 `v11s640_clsbal`（`cls_pw=0.5`）。
两者其余超参**逐键相同**：`imgsz=640`、`batch=24`、`epochs=100`、`fraction=1.0`、
`scale=0.5`、`mixup=0.0`、`model=yolo11s.pt`、同一数据集。

> ⚠️ **一处必须声明的差异（不是「唯一变量」）**：两次训练的
> `workers` **不同** —— 基线 `workers=0`（2026-09-21 14:11 开跑，早于提速改动），
> 实验 `workers=4`（`COMMON_ARGS` 于 09-21 改为 4 之后）。
> `workers` 只改变 dataloader 进程数与加载速度，**不改变损失数学与增强分布**，
> 但严格意义上本实验是「单主变量（`cls_pw`）+ 一处工程参数差异」的 A/B，
> **报告中不得写成「唯一变量 = cls_pw」**。

#### 7.8.6 判读纪律与预期管理

**本节采用与 §7.4/§7.3 相同的可比较性纪律**（见 §3.3 CI 半宽表）：
单种子单次训练下，**组间方差本身即可能与 0.03 同量级**
（§7.4 数据增强 A/B 实测：唯一变量 `scale 0.5→0.9` + `mixup 0→0.15`，
跑满 100 轮后 mAP50 仅 +0.0036，逐类全部落在 CI 内）。

因此本实验的**定位必须说清楚**：

- ✅ **本实验主张的是**：「针对 45.6 : 1 的类别长尾，实现并验证了逆频率类平衡损失
  （`cls_pw=0.5`），把有效损失占比从 45.6 : 1 收敛到 6.75 : 1」——
  这是**可复算的工程事实**，且经三重验证确认生效。
- ❌ **本实验不主张**：「类平衡损失提升了 mAP」。
  若实测差异小于 CI 半宽（很可能如此），**必须如实写「未测出可测量差异」，
  不得虚报提升**。
- 若稀有类（`spalling` / `crack` / `moss`）召回有改善而整体 mAP 持平，
  这本身是有价值的发现（说明权重确实作用在目标类上），但**仍须逐类对照 CI 半宽**。

> ★ 诚实报告「无显著差异」比虚报提升更有说服力 —— 本节的价值在于
> **规范地完成了一次损失函数优化**（对应赛题「技术深度·模型结构改进」项），
> 而**不是**在于刷新一个更高的 mAP 数字。
