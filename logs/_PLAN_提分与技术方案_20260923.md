### ① 数据增强创新（+3）

| 项 | 内容 |
|---|---|
| **难点** | 普通的 mosaic/flip 不算创新。必须针对**本项目的特有痛点** |
| **我们的痛点** | ① 极端长尾：`rust` 13685 框 vs `spalling` 313 框 = **43:1**；② 小目标为主（裂缝/露筋在图上很小） |
| **推荐方案 A** | **长尾定向 Copy-Paste 增强** —— 把稀有类（`spalling` / `exposed_rebar` / `delamination`）的实例抠出，粘贴到其他图上。有文献支撑（Simple Copy-Paste, CVPR 2021），**直接对口 43:1 长尾** |
| **推荐方案 B（更有本项目特色）** | **GSD 感知的尺度增强** —— 我们的关键物理变量是 GSD（拍摄距离）。增强时**按 GSD 的物理区间**（而不是随便取 0.5~1.5）缩放整图，模拟 5m/20m/50m 三种拍摄距离。**把物理约束引入数据增强**，这是别人不会做的 |
| **成本** | 1 次训练 ≈ **2.8 h** + 评估 |
| **风险** | 中。可能改善稀有类但整体 mAP 持平 —— 那就**按类报告**（稀有类提升即成立） |
| **证据要求** | A/B 对照表（baseline vs +增强），**必须按类看**，不能只看总 mAP |

### ⚠️ 两条红线（必须遵守，否则有合规风险）

1. **不要直接打包上传数据集**。我们的数据来自 4 个公开数据集，**许可各不相同**
   （有一个是 Apache-2.0）。正确做法：**只放构建脚本 + 来源清单 + 各来源许可说明**，
   让别人自己去下载。README 里要写清「本仓库不含数据集，请按 NOTICE-DATASETS.md 自行获取」。
2. **推送前必须脱敏**：清掉本机绝对路径（`D:\pythonstudy 备份\...`、`D:\下载\python.exe`）、
   以及任何账号/密钥。我们代码里已有大量绝对路径（属调试痕迹）。

## 三、P0-2 提速：问题已彻底劈开 —— **到底要哪个**

### 四组实测汇总

| 组 | 结论 |
|---|---|
| **分辨率** | 640→512 = **0.99×**；640→448 = **1.03×（几乎无收益）** |
| **FP16** | **0.43×（慢 2.3 倍，负优化）** |
| **换小骨干** | v8n@640 = **1.12×**；v8n@320 = **1.43×**（算力降到 **1/12** 只换 1.43×） |
| **批量** | batch=4 = **1.81×**；batch=8 = **1.95×**（4~8 饱和） |
| **耗时劈分** | 裸前向 **51.3%** / 包装调度 **29.4%** / 预处理 13.8% / NMS 5.4% |

### 三条结论

1. **单图（batch=1）已接近地板**。算力降到 1/12 只快 1.43× ⇒ 时间由**GPU 单次启动 + 调度**主导，
   不是算力。所以「换小模型」「降分辨率」两条路**彻底堵死**。
2. **自写精简推理路径最多省 ~4.5 ms（1.42×）** —— 因为一半时间（51.3%）是真的在算。
   **收益小、要重写推理链路、有精度风险** ⇒ **我不建议做**。
3. **批量是唯一有实质收益的方向（1.95×）**，而且它摊薄的正是那个"启动+调度"成本。

### 推荐：按这个顺序，明确取舍

| 选 | 做什么 | 收益 | 理由 |
|---|---|---|---|
| **① 必做** | **批量推理接进 `--dir`** | **1.95×** | 对口"海量筛查"这个**我们自己的主张场景**；可主张部署优化/实时性；风险低 |
| **② 必做** | **`_thin_skeleton` 提速** | 真实照片 **5.1s → <1s** | 收益数量级最大；**这才是真实用户感受到的"慢"** |
| ③ 可选 | 自写精简推理路径 | 1.42× | ❌ 不建议（收益小风险大） |
| ④ 不做 | FP16 / 降分辨率 / 换小骨干 / ONNX-GPU | 负或无 | 实测已否决；ONNX-GPU 还会毁环境 |

> **一句话取舍**：「**单张再快没有意义（已到地板），要快就快在批量和真实照片上。**」

## 四、赛道五：GradCAM 是什么 + 需要做什么 + 计划表

### GradCAM 是什么（通俗版）

**Grad-CAM = 梯度加权类激活映射** —— 一种回答「**模型是看着图上哪块地方做出判断的**」的可视化方法。

做法：取模型某一层的特征图，用「该类别对特征图的梯度」当权重加权求和，
再叠到原图上，得到一张**热力图**：颜色越红的地方，模型越"关注"那里。

**用途**：验证模型**是不是看对了地方**。例：判断"这是狗"时，热力图若盖在狗身上 → 看对了；
若盖在背景草地上 → 模型学偏了。

### 我们做了 GradCAM 吗？

**没有。全库没有 GradCAM / CAM / 注意力热力图。** 一个字都没做。

### 但我们的「可解释」比 GradCAM 更硬 —— 这点必须在答辩上讲清楚

| | GradCAM（赛道五常见做法） | **我们的做法** |
|---|---|---|
| 回答的问题 | 模型**看哪里** | **这张图够不够格下结论** |
| 依据 | 梯度统计（**启发式、不保证因果**） | **可复算的几何判据**：目标实际尺寸 ÷ GSD = 图上几个像素，是否达到判读门槛 |
| 可验证性 | 只能"看起来合理" | **任何人拿计算器都能复算**（0.3mm ÷ 0.5mm/px = 0.6px < 3px 门槛） |
| 对决策的作用 | 间接 | **直接**：判不到就拒答，并说清为什么拒 |

⇒ **我们不是"没做可解释"，而是换了一条更硬的路。** 这句话要在答辩上主动说。

### 走赛道五需要做什么（计划表）

赛道五的官方技术挑战是三条：**注意力可视化（GradCAM等）/ 多任务学习 / 人机交互界面设计**。
我们**已有**人机交互界面（Gradio 应用 + 收集站）+ 可解释性（几何判据）。缺的是"把可解释性做成可交互"和"用户验证"。

| 阶段 | 任务 | 产出 | 依赖 | 预计 |
|---|---|---|---|---|
| **T1 定位** | 在 README / PPT / 答辩材料里**明确写「最接近赛道五」**，并附那句"几何判据 vs 注意力图"的限定说明 | 三处各一段 | 无 | 0.5 h |
| **T2 可交互解释（正路）** | 界面上把「为什么判不了」做成**可展开的判据推导**：点一下看到 `0.3mm ÷ 0.06696 mm/px = 0.0045px < 3px` 的完整算式与门槛来源 | `app.py` 加一个展开区 | T1 | 2~3 h |
| **T3 （可选）补 GradCAM** | 给一张示例图加 GradCAM 热力图，**并明确标注**："它回答的是'看哪里'，与我们回答的'够不够格'是两件事" | 一张对比图 + 报告一小节 | 需装 `pytorch-grad-cam` | 2~3 h |
| **T4 用户测试（补 HCI 证据）** | 找 **5~10 个同学**试用界面，记录：能否看懂「判不了」、卡在哪里；据此改 1~2 处 | 一页反馈汇总 + 改动说明 | T2 | 2~3 h（含等人） |
| **T5 收口** | 把 T2/T4 写进技术报告新一节「可解释性与人机交互」 | 报告一节 + PPT 1 页 | T2/T4 | 1~2 h |

> **T4 的额外好处**：它同时把「实机演示**或**用户测试反馈（+3）」从"只有实机演示"变成"两者都有"，
> 证据更硬（虽然那条是"或"，但两条都具备更稳）。
>
> **建议**：**T1 + T2 + T4 是核心**（真正提升赛道五的契合度）；T3 可选（补一张图证明我们了解 GradCAM）。
