## 一、一句话结论

**「实时」在当前工程内是达成的，但只对 GPU 成立；CPU 不可实时。**

## 二、实测数字（口径严格区分）

### 2.1 GPU（cuda:0）— **可实时**

来源：`logs/rt_metrics_synthetic_20260927_122234.json`（复跑）；与首跑 `logs/_gpu_bench_full.log` 交叉核对。

| 指标 | 首跑 | 复跑 | 说明 |
|---|---|---|---|
| 单帧推理 mean | 61.563 ms | 62.234 ms | 差 1.1% |
| 单帧推理 p50 | 64.184 ms | 65.179 ms | — |
| 单帧推理 p90 | 69.217 ms | 72.368 ms | 差 4.6% |
| 单帧推理 p99 | 71.083 ms | 72.712 ms | — |
| **吞吐 FPS（稳态口径）** | — | **16.07** | 阈值 15.0 ⇒ **通过** |
| 吞吐 p90 口径 | — | 13.82 | — |
| 端到端延迟 p90 | 102.245 ms | 132.017 ms | 阈值 200.0 ⇒ **通过** |
| 取帧耗时 mean | 2.709 ms | 2.679 ms | ⇒ 瓶颈 = **模型推理**，不在解码 |

**类别命中两次完全一致**：`{'crack': 19, 'spalling': 2, 'efflorescence': 15}` —— 这比时间数字更有力，
说明复跑是同一份确定性的计算，差异纯粹来自 GPU 调度抖动。

### 2.2 CPU（cpu）— **不可实时**

来源：`logs/rt_metrics__loopback_20260927_094900.json`（回环 UDP，端到端链路自测，8 帧统计）

| 指标 | 数值 |
|---|---|
| 单帧推理 p50 | 549.77 ms |
| 单帧推理 p90 | 595.635 ms |
| 端到端延迟 p90 | 710.42 ms |
| 吞吐 FPS | **0.43**（1.846 是单帧反推的乐观口径） |
| `realtime_ok` | **false** |

### 2.3 结论表

| 设备 | 单帧推理 p50 | 吞吐 | 能否实时 | 19× 差距 |
|---|---|---|---|---|
| CPU | ~550 ms | ~0.43 fps | ❌ | 1× |
| **GPU** | **~65 ms** | **16.07 fps** | ✅ | **~19×** |

> ⇒ **交付/演示必须用 GPU。** 若现场只能用 CPU，须如实声明「为事后分析型，非实时」。

## 六、设计上主动规避的坑（都写进了代码注释）

| 坑 | 规避 |
|---|---|
| 参数键名不匹配 → **静默**回落默认值 | `build_args()` 集中做键名映射；非法 `env_class` 直接报错 |
| 标定链兜底 `distance<=0` 跑一半崩 | 配置给正数默认 + 启动期预检 |
| 预热吃光帧数 → 统计为空却「显示成功」 | 预热独立预算；零样本时打印「无效实验，不得用于性能结论」 |
| `cv2.putText` 不支持中文 → 标签变 `?` | 中文层走 PIL（微软雅黑/黑体），cv2 只画 ASCII |
| GPU 计时未同步 → 测到的是「发起调用」时间 | `Seg` 进出都 `torch.cuda.synchronize()` |
| 逐帧写盘再读盘传路径 → 纯 I/O 浪费 | 走 `run_one(image=frame)` 内存帧入口 |
| 检测框样式各写一套 → 与主链路不一致 | 直接用 `run_one` 返回的 `annotated`，本层只追加中文标签与 HUD |
| 同类缺陷颜色静默回退 → 配图误标 | `CLASS_COLORS` 与 `pipeline.py` 逐项一致，含全部 7 类 |
