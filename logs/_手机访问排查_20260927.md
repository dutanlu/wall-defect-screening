# 手机访问排查记录（2026-09-27）

## 现象
网页说明里写「手机打不开通常是 Windows 防火墙拦了 7860 端口」，
但**实测这台机器上不是防火墙的问题**。

## 实测证据

| 检查项 | 命令/来源 | 实际结果 |
|---|---|---|
| 网络类型 | `Get-NetConnectionProfile` | WLAN「HONOR-5102SO」，**Category=Public** |
| 防火墙 Public 档 | `Get-NetFirewallProfile` | **Enabled=True**（开启） |
| Python 入站规则 | `Get-NetFirewallRule` | **已存在 2 条**：Program=`D:\下载\python.exe`，Protocol=TCP / UDP，LocalPort=**Any**，Profile=Public，Action=Allow |
| 7860 实际监听地址 | `Get-NetTCPConnection -LocalPort 7860` | **LocalAddress=127.0.0.1**（只绑本机） |

## 结论（重要，纠正网页那句话）

**防火墙已经放行了**（Public 档就有 Python 的 TCP 全端口放行规则，
且当前网络正好是 Public 档 ⇒ 规则生效）。

**手机打不开的真正原因是监听地址**：
`app.py` 默认 `server_name="127.0.0.1"` ⇒ 只有本机能连，
局域网里其它设备（手机）**根本没有入口**，跟防火墙无关。

## 正确做法

启动时显式绑到 0.0.0.0：

```
D:\下载\python.exe app.py --host=0.0.0.0
```

（本工程已在 `06_deploy/app.py` 实现了 `--host=` 参数；
不加时默认 127.0.0.1，保持安全。）

然后手机浏览器打开 `http://192.168.3.215:7860`。

## 若确实需要手动加防火墙规则

只有在**没有** Python 放行规则、或规则绑的是别的 python.exe 路径时才需要。
命令（**需要管理员权限的 PowerShell**）：

```powershell
# 给当前使用的解释器加 7860/7861 入站放行（TCP）
New-NetFirewallRule -DisplayName "外墙缺陷筛查 7860/7861" `
  -Direction Inbound -Protocol TCP -LocalPort 7860,7861 `
  -Action Allow -Profile Private,Public -Program "D:\下载\python.exe"
```

> 本机**不需要**执行——因为已有等效规则（`D:\下载\python.exe` + TCP + Any 端口）。

## 附：各档防火墙开关

| Profile | Enabled |
|---|---|
| Domain | True |
| **Private** | **False** |
| Public | True |

> 注意：**Private 档是关的**。若将来换到被识别为 Private 的网络，
> 防火墙整体不拦（那档关着），也不需要加规则；
> 真正要留意的只有 Public 档（当前就是），而它已经有放行规则了。
