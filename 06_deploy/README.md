# 06_deploy —— Web 演示应用

外墙缺陷智能筛查系统的可视化演示界面。
**提交的「实机运行视频」就是用这个程序录的**（Playwright 驱动真实浏览器操作它）。

## 运行

### 方式一：双击启动（推荐）

双击本目录下的 **`run_app.bat`** —— 会自动启动服务并打开浏览器
（地址 `http://127.0.0.1:7860`）。用完关掉那个黑窗口即停止服务。

> 同目录的 `启动说明.txt` 里有完整的用法与三种结果示例。
> `.bat` 内容为 GBK 编码（因为含中文路径 `D:\下载\python.exe`），**勿用 UTF-8 编辑器保存**。

### 方式二：命令行

```powershell
$PY = "D:\下载\python.exe"
cd "D:\pythonstudy 备份\创新题\外墙缺陷筛查\06_deploy"
& $PY app.py                       # 默认 http://127.0.0.1:7860
& $PY app.py --port=7861           # 换端口
```

## 界面设计说明

界面刻意对齐本项目的核心主张 —— **系统必须主动暴露自己的能力边界**。
因此结果区固定按这个顺序呈现，顺序本身也是设计的一部分：

1. **状态徽标**（GSD / 标定置信度 / 检出数）—— 先给「这张图有多可信」
2. **可判读性结论文本** —— 三类：可给毫米级结论 / 部分可判读 / 拒绝给结论
3. **房屋危险性等级** A/B/C/D/**U**
4. **检出明细表** —— 不可判读的条目尺寸结论已作废，显示为「尺寸不可判定」
5. **本图能力边界诚实清单** —— 逐项目标：实际尺寸 / 图上像素 / 是否可用
6. **免责声明** —— 筛查排序，非法定鉴定

### 「尺度标定」面板为什么要写那么多说明（2026-09-22 补）

三种标定方式（相机参数估算 / 标定物 / 砖缝周期）的输入框**是同时显示的**，
但实际**只有被选中的那种参与计算** —— 这一点不看说明根本猜不到，用户实测反馈
「看不懂哪个该填」。因此面板顶部加了：

1. 一张 **「标定方式 → 需要你填的框 → 什么时候用」** 对照表；
2. 一句明确结论：**没选中的框不参与计算，保持默认值即可**；
3. 每个输入框各自的 `info` 说明（含常用取值，如「一元硬币直径 25」「手机主摄约 24」）；
4. 一段「为什么标定物最准」的提示 —— 强调相机参数估算的误差会**成正比**放大到毫米数。

> 「标定物像素宽度」的默认值 0 表示**未标定**，说明里已写清；
> 该框的 `aria-label` 也随之改成了「标定物像素宽度（标定物在图上占多少 px）」。
> ⚠️ `logs/_record_demo.py` 里定位该框用的是 **`aria-label*=` 包含匹配**，
> 所以以后再改标签文案也不会把录制脚本弄坏。

### 视觉主题

与照片收集站（`08_photo_collector/site/`）共用同一套视觉语言：
**白底 + Apple 式中性灰阶 + 多色渐变点缀（蓝 → 青 → 紫）**。
定义在 `app.py` 顶部的 `APP_CSS`，色彩令牌与收集站一一对应。

**为什么强制浅色而不跟随系统主题**：

1. **投屏友好** —— 演示场景是教室/会议室投屏。深色界面经投影仪输出后
   对比度会被压扁、暗部糊成一片；浅色白底投出来更干净、字更清楚。
2. **「拒绝下结论」的提示仍然醒目** —— 浅色下不靠"暗底"抓注意力，
   而是给这类提示**饱和的彩色渐变边条 + 同色浅底**（见 `APP_CSS` 里
   `.prose blockquote` 的 `border-image`），投影后依然是全场最跳的色块。
3. **两处只需维护一套配色** —— 收集站与演示应用不再各有一套。

> ⚠️ `theme` / `css` / `head` 在 **Gradio 6+ 必须传给 `launch()`**，
> 传给 `Blocks()` 只会静默失效（界面能跑但美化全丢）。见 `_theme_and_style()`。

## 已知环境限制

- `--share` 走 gradio.live 隧道，本机网络下 CONNECT 会 502。
  **演示前务必先测通**；不通则改用局域网 IP，让评委在同网段访问。
- 模型首次推理需加载权重（约 2–5 秒），实际演示前**先跑一次预热**，
  避免评委面前等加载。
