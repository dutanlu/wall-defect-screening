## 一、裂缝宽度限值（GB 50010-2010 表 3.4.4）

规范明确：**裂缝宽度以构件混凝土表面实测最大值为准**。

| 环境类别 | 最大裂缝宽度限值 |
|---------|---------------:|
| 一类环境（室内干燥） | **0.30 mm** |
| 二类环境（露天/潮湿） | **0.20 mm** |
| 三类环境（干湿交替/海风） | **0.20 mm** |

> 外墙属**二类环境**（露天），故系统默认用 **0.20 mm** 判裂缝超限。
> 代码位置：`02_code/gsd.py:62-66`（`GB50010_LIMITS_MM`）

## 二、危险点判据（JGJ 125-2016）

| 判据 | 阈值 |
|------|----:|
| 梁板受力主筋处横向/斜裂缝 | **0.50 mm** |
| 板受拉裂缝 | **1.00 mm** |

> 判据**优先于** GB 50010 的环境限值：一旦命中即为 `danger`。
> 代码位置：`02_code/gsd.py:68-71`（`JGJ125_DANGER_MM`）

### 房屋危险性等级（对齐 JGJ 125-2016 的 A/B/C/D 思路）

| 等级 | 含义 |
|------|------|
| **A** | 结构承载力能满足正常使用要求，未发现危险点，房屋结构安全 |
| **B** | 结构承载力基本能满足正常使用要求，个别构件存在危险点，但不影响主体结构安全 |
| **C** | 部分承重结构承载力不能满足正常使用要求，局部出现险情，构成局部危房 |
| **D** | 承重结构承载力已不能满足正常使用要求，房屋整体出现险情，构成整幢危房 |
| **U** | **无法判定** —— 由本系统新增，非国标等级（见下文第四节） |

> 代码位置：`02_code/grade.py:40-45`（`RISK_LEVELS`）

## 三、可判读性门槛（本项目的创新核心）

| 常量 | 值 | 含义 |
|------|----|------|
| `MIN_RELIABLE_PX` | **3.0 px** | 最小可判读像素数；**低于此值测量误差 > 1 个国标分级步长** |
| `COMFORTABLE_PX` | **8.0 px** | 毫米级测量的舒适门槛；至少 8px 才能稳定做骨架化/距离变换 |

> 代码位置：`02_code/gsd.py:74-76`

**这两个门槛把「规范和图像」连了起来**：
判读 0.3mm 裂缝（≤3px 即不可靠）需要 **GSD ≤ 0.1 mm/px**；
而地面拍摄（主摄需贴近到 27cm）根本达不到 —— 这就是「地面拍高层
在物理上判不了 0.3mm 裂缝」的量化依据，也是系统拒答的触发条件。

## 四、逐类分级判据与输出规则

| 类别 | 主判据 | 规则 | 代码 |
|------|--------|------|------|
| `crack` 裂缝 | `width_max_mm` | JGJ 125 危险点优先；否则比 GB 50010 环境限值，**超 2 倍升 danger**，超 1 倍为 attention；最大宽度 < 8px 时追加低置信度提醒 | `grade_crack` |
| `spalling` 剥落 / `efflorescence` 泛碱 / `exposed_rebar` 露筋 / `delamination` 空鼓 | `area_ratio` | 面积占比 **≥15% → danger**，**≥5% → attention**（**工程经验阈值，非国标强制限值**，代码内已显式声明） | `grade_blob` |
| `moss` 苔藓 | `area_ratio` | **上限只到 attention**（≥5%），不计入承载能力判定 | `grade_moss` |

**两处刻意设计（避免误报）**：

1. **露筋**：只要检出即至少 `danger` —— 钢筋失去保护层后会持续锈蚀，
   削弱有效截面并可能胀裂混凝土。
2. **苔藓**：**最高只到 attention**。苔藓不削弱承载力，但它是「长期潮湿」的
   可靠指示物。若按通用块状规则走，一块 15% 面积的苔藓会被判成 `danger`
   并把整栋楼推到 C 级 —— 属典型误报。故其 `extra.is_structural = False`，
   在建筑等级判定中**被排除**，另行汇总为「潮湿线索」（`n_moisture_hints`）。

### 建筑等级合成规则

```
存在 danger 且数量 ≥ 3，或 danger 中含 exposed_rebar  → C
存在 ≥ 1 个 danger                                    → B
仅存在 attention                                      → B
否则                                                  → A
```

**只统计结构类缺陷**；苔藓等非结构项不参与升级。

> 代码位置：`02_code/grade.py:243-291`（`building_risk_level`）

## 五、`U` 级（无法判定）—— 本系统新增的等级

国标体系里没有 `U`。本系统新增它，是因为**「判不了」不等于「没问题」**。

- **触发**：当所有条目都不可判读（GSD 不足）时，风险等级输出 **`U`** 而非 `A`。
- **含义**：把「无法判定」报成「安全」是最危险的误报 —— 会让人以为楼是好的。
- **配套**：`risk['n_unjudgeable']` 记录被作废的条目数；
  一旦判定某类不可判读，该类**所有条目的定量结论全部作废、连 `reason` 文本一起重写**，
  确保荒唐数字不会从任何字段漏出去（详见技术报告 §2.3「拒答传染到输出层」）。
- **界面实现**：`06_deploy/app.py`（`grading_rules.json` 的
  `unjudgeable_level_U` 字段记录了出处）。
